# Overchat Analytics Kit

Всё, что нужно другому Claude, чтобы считать аналитику Overchat так же, как в этом чате:
методология без ошибок, глоссарий событий, шаблоны SQL и подключение к BigQuery.

## Что внутри

```
skill/
  SKILL.md                      ← ГЛАВНОЕ: правила работы, окна сравнения, форматы, грабли
  references/
    database-schema.md          ← таблица, двойная схема, дедуп, NULL-ловушка, покупки/методы. ЧИТАТЬ ПЕРВЫМ
    sql-templates.md            ← проверенные шаблоны запросов (палитра, воронка, трафик, длительность)
    pricing-revenue.md          ← цены планов, расчёт дохода/среднего чека, сверка со Stripe
    event-taxonomy.md           ← полный глоссарий всех событий + накопленные инсайты/разборы
                                   (Google Pay, дваждыфайр, воронки; = dashboard/EVENTS.md, живой файл)
  assets/
    excluded_users_cte.sql      ← CTE тест-юзеров — вставлять первым в КАЖДЫЙ запрос
connection/
  BQProxy.gs                    ← прокси на Apps Script: даёт Claude read-only доступ к BQ (инструкция внутри)
  bq_client.py                  ← питон-клиент к прокси (подставить URL + токен)
```

## Как подключить к другому Claude

### Вариант А — Claude Code (в терминале / на claude.ai/code)
1. Скопировать папку `skill/` в `~/.claude/skills/overchat-analytics/`
   (или в `.claude/skills/overchat-analytics/` внутри проекта).
2. Всё — скилл подхватится сам, Claude будет применять правила при любом вопросе про аналитику.

### Вариант Б — обычный Claude (веб / приложение)
Приложить эти файлы в проект/контекст и сказать:
> «Считай аналитику Overchat по этим правилам. Сначала прочитай database-schema.md, потом
> действуй по SKILL.md. Тест-юзеров исключай через excluded_users_cte.sql в каждом запросе.»
Ключевые файлы по важности: `database-schema.md` → `SKILL.md` → `sql-templates.md` →
`pricing-revenue.md`. `event-taxonomy.md` и `EVENTS-insights.md` — справочники под руку.

## Как дать Claude доступ к данным (BigQuery)

Claude НЕ подключается к BQ напрямую. Доступ идёт через прокси-веб-приложение, которое
разворачиваешь ты под своим аккаунтом:

1. Открыть `connection/BQProxy.gs` — внутри пошаговая инструкция (5 минут):
   создать Apps Script проект, включить BigQuery API, вписать project id, задать секретный
   токен, задеплоить как Web app.
2. В `connection/bq_client.py` подставить URL веб-аппа и токен.
3. В новом чате прислать Claude: URL, токен и путь к таблице
   (`project.dataset.events_*`). Дальше он сам пишет и гоняет запросы.

⚠️ **Токен — это пароль к твоим данным.** Не публикуй его, делай отдельный на каждый проект.
Прокси пускает только SELECT (read-only), режет запись, ставит потолок скана.

## Как обновлять

Файлы — живые. Когда находится новый нюанс данных (новое событие, баг трекинга, смена
схемы), дописывай в `database-schema.md` / `event-taxonomy.md` / `EVENTS-insights.md`, чтобы
следующий Claude не спотыкался. В этом и весь смысл кита — накопленное знание, а не разовые запросы.
